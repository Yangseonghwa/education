# 중학교 과학 수업을 위한 프리젠테이션 제작 방식 비교 분석 및 Gemini Notebook 통합 수업설계 아키텍처 (v3.0)

- **작성일**: 2026-11-08
- **적용 대상**: 중학교 과학(중1~중3) 수업 설계 (시나리오 → 프리젠테이션 → 마무리 학습지 → 교사 성향 누적·지침 개선)
- **핵심 과제**: 교육 계정 Gemini 슬라이드(3.6 Flash 기반) 제작 방식과 강화된 **Gemini Notebook(구 NotebookLM) 스튜디오(Slide Deck)** 자체 제작 방식의 장단점을 다각도로 비교하여 최적의 워크플로우를 확정하고, 이를 뒷받침하는 **상세 지침(v3.0)**·**채팅 맞춤설정**·**성향 누적 자가발전 구조**를 구축함.

## 1. 핵심 의사결정: 스튜디오(Slide Deck) vs Gemini 슬라이드(3.6 Flash)

### 1.1 두 방식의 기술적·교육적 특성 비교

중학교 과학 수업(입자의 운동, 샤를·보일 법칙, 여러 가지 힘, 옴의 법칙, 별의 등급과 색, 화학 반응 등)의 관점에서 두 도구를 7가지 핵심 기준으로 비교 분석했습니다.

| 비교 항목 | **Gemini Notebook 스튜디오 (Slide Deck)** | **교육 계정 Gemini 슬라이드 (3.6 Flash)** | 중학교 과학 수업 관점 판정 |
| :--- | :--- | :--- | :--- |
| **① 전체 시각·이미지 품질** | **최상 (Nano Banana Pro 기반 렌더링)**<br>슬라이드 전체를 인포그래픽·다이어그램·비유 삽화가 조화된 고해상도 비주얼 레이아웃으로 생성 | **보통~낮음 (텍스트 박스 + 기본 도형 위주)**<br>개조식 텍스트 요약 위주이며 레이아웃이 단조롭고 과학 개념 삽화 품질이 제한적 | **스튜디오 압승**<br>시각적 직관성이 생명인 중학교 과학에서 학생 몰입도 차이가 매우 큼 |
| **② 과학 모형·현상 비교 표현력** | **우수**<br>거시적 현상(예: 찌그러진 탁구공)과 미시적 모형(입자 충돌 화살표), 대조 레이아웃을 한 장에 직관적으로 시각화 가능 | **미흡**<br>교사가 별도로 시뮬레이션 캡처나 교과서 그림을 찾아 수동으로 붙여 넣어야 함 | **스튜디오 우위**<br>단, 스튜디오가 과학적 오류(화살표 방향 등)를 범하지 않도록 **사전 설계 프롬프트 통제** 필수 |
| **③ 완성 후 부분 편집성** | **제한적 (래스터/이미지 기반 한계)**<br>스튜디오 슬라이드는 이미지 렌더링 방식이라 `.pptx`로 내려받아도 글자 단위 직접 클릭 수정이 어렵고, 스튜디오 내 `Revise(수정)` 기능으로 슬라이드별 재생성을 해야 함 | **최상 (네이티브 Google Slides 개체)**<br>모든 텍스트 상자·도형·표를 마우스로 클릭해 1초 만에 수정·삭제·서식 변경 가능 | **Gemini 슬라이드(Flash) 우위**<br>학급별 실시간 빈칸 입력·오타 즉석 수정은 네이티브 슬라이드가 유리 |
| **④ 수정(`Revise`) 시 원본 소스 참조 여부** | **주의 필요 (2026 스튜디오 구조적 제약)**<br>최초 생성 시에는 소스를 읽지만, 생성 후 `Revise` 모드에서는 **원본 소스를 다시 읽지 않고** 수정 지시문만으로 새 덱을 재생성하며 쿼터를 소모함 | **프롬프트 재입력 또는 수동 편집**<br>교사가 직접 슬라이드에서 고치므로 AI 재생성 자체가 불필요 | **사전 아웃라인 확정으로 해결**<br>스튜디오 생성 전에 채팅에서 슬라이드 설계안을 먼저 확정해야 `Revise` 반복을 막을 수 있음 |
| **⑤ 한글 텍스트 렌더링 안정성** | **글자 수가 적을 때 우수 / 많을 때 깨짐 위험**<br>이미지 렌더링 특성상 한 슬라이드에 긴 문장이나 복잡한 표가 들어가면 한글 자소 깨짐·오탈자 발생 가능 | **완벽 (시스템 폰트 텍스트)**<br>긴 문장이나 복잡한 실험 결과표도 글자 깨짐이 전혀 없음 | **역할 분리로 해결**<br>스튜디오 슬라이드는 **핵심 키워드·발문(3줄 이내)**만 넣고 긴 설명·표는 시나리오·학습지로 분리 |
| **⑥ 교과서 근거 충실도 (할루시네이션 통제)** | **우수 (노트북 내 선택 소스 기반)**<br>선택된 소스(교과서·지도서·확정 시나리오 노트) 안에서만 내용을 추출 | **보통**<br>채팅에서 만든 긴 프롬프트를 옮기는 과정에서 일부 조건이 누락되거나 일반 지식이 섞일 수 있음 | **스튜디오 우위**<br>노트북 안에서 시나리오→프리젠테이션→학습지가 한 맥락으로 묶임 |
| **⑦ 교사 작업 동선 (Context Switching)** | **원스톱 (Gemini Notebook 내부 완결)**<br>채팅 설계 → 노트 소스 고정 → 스튜디오 생성까지 하나의 노트북 안에서 진행 | **이원화**<br>노트북 채팅에서 프롬프트 생성 → 복사 → Gemini/Google Slides 이동 → 생성 후 수동 편집 | **스튜디오 우위**<br>단원별 노트북 하나에 모든 수업 자산이 축적됨 |

### 1.2 최종 채택 전략: **"스튜디오 중심(Primary 85%) + 부분 편집 3대 보완(Hybrid 15%) 파이프라인"**

> **결론**: 전체적인 프리젠테이션의 시각적 완성도와 중학교 과학의 생명인 **'현상-모형 시각화 품질'**을 극대화하기 위해 **Gemini Notebook 스튜디오(Slide Deck) 자체 제작 방식을 주력(Primary) 프로세스로 채택**합니다. 동시에 스튜디오의 유일한 약점인 **'부분 편집의 불편함'과 '교사 시나리오 의도 반영 문제'를 4단계 브릿지 기술로 완벽히 보완**합니다.

#### 스튜디오의 약점을 해결하는 4대 핵심 엔지니어링 기법

1. **[기법 1] '확정 설계안의 소스화 (Note-to-Source Pinning)'로 교사 의도 100% 강제**
   - 스튜디오에서 바로 교과서 PDF만 선택해 슬라이드를 만들면 AI가 임의로 교과서를 요약해 버립니다.
   - 대신 **① 채팅에서 인터랙티브 아웃라인으로 시나리오 확정 → ② 채팅에서 스튜디오용 슬라이드 설계안(장별 제목·표시 문구·시각 모형 지시) 확정 → ③ 이 확정 설계안을 노트북의 `[메모(Note)로 저장]` 후 `[소스로 변환(Convert to source)]` → ④ 스튜디오 Slide Deck 생성 시 이 '확정 설계안 소스'를 핵심 소스로 선택**하여 생성합니다.
   - 이렇게 하면 스튜디오의 고품질 이미지 엔진이 **교사가 확정한 시나리오 흐름과 발문 순서대로만** 슬라이드를 그려냅니다.

2. **[기법 2] '1슬라이드 1메시지 · Text-Light, Visual-Rich' 한글 깨짐 원천 차단 규칙**
   - 스튜디오 렌더링 후 글자를 일일이 고칠 필요가 없도록, 애초에 슬라이드 화면에 들어갈 텍스트를 **제목 1줄(15자 이내) + 핵심 문구/발문 2~3줄(줄당 20~25자 이내, 개조식)**로 제한합니다.
   - 교사의 상세한 설명 대사, 예상 학생 반응, 실험 유의사항은 슬라이드에 적지 않고 **확정 시나리오(교사용 대본)**에 두며, 학생이 읽고 써야 할 긴 문장과 표는 **마무리 학습지**에 배치합니다.

3. **[기법 3] 스튜디오 생성 전 'Review outline notes(아웃라인 노트 검토)' + 생성 후 '자가 완결형 Revise 지시문'**
   - 스튜디오 Slide Deck 생성 시 **아웃라인 검토(Review outline notes)** 옵션을 켜서 렌더링 전에 슬라이드 구성을 한 번 더 고정합니다.
   - 렌더링 후 일부 슬라이드(예: 4번 슬라이드의 입자 화살표 길이, 6번 슬라이드의 오타)만 수정하고 싶을 때는 스튜디오의 `Revise(수정)` 모드를 쓰되, **`Revise` 모드는 원본 소스를 다시 읽지 않으므로** 노트북 채팅에서 `/프리젠테이션-부분수정` 명령을 통해 **정확한 과학 용어·수치·수정 문구가 모두 포함된 '자가 완결형 슬라이드별 Revise 지시문'**을 뽑아 `Pending Changes`에 한 번에 입력합니다.

4. **[기법 4] 실시간 판서·빈칸 입력용 슬라이드만 '부분 오버레이' 또는 'Gemini 3.6 Flash 부분 패치' (`/슬라이드-플래시패치`)**
   - 수업 중 교사가 전자칠판이나 슬라이드에서 학급별 실험 측정값을 실시간으로 타이핑해야 하는 표 슬라이드, 또는 매 반마다 단어를 바꿔야 하는 1~2장의 슬라이드가 있을 수 있습니다.
   - 이 경우 ① 스튜디오에서 `.pptx`로 내려받아 해당 슬라이드 위에만 투명/흰색 텍스트 박스를 얹거나, ② 채팅에 `/슬라이드-플래시패치 [슬라이드 번호]`를 요청해 **해당 1~2장만 교육 계정 Gemini(3.6 Flash)로 즉시 편집 가능한 Google Slides로 생성**하여 끼워 넣습니다.

## 2. 중학교 과학 맞춤형 인터랙티브 수업설계 3대 산출물 구조

교사의 기존 수업 철학(`00_최우선지침_v2.0` 및 중1 샤를 법칙·힘, 중2 옴의 법칙 시뮬레이션 등)을 분석하여, 중학교 과학 수업에 가장 효과적인 **5단계 과학 인지 흐름**을 모든 산출물의 뼈대로 내재화했습니다.

### 2.1 중학교 과학 5단계 핵심 인지 흐름 (Scientific Cognitive Flow)
1. **[Step 1. 전수업 연결 & 개념의 필요성(Need-to-Know)]**: 법칙·용어를 바로 정의하지 않고, 기존 상식으로 설명되지 않는 일상 현상이나 질문을 던져 학생 머릿속에 **'이 개념이 왜 필요한지' 받아들일 자리**를 먼저 만든다.
2. **[Step 2. 복잡한 현실 현상 관찰(Macro Phenomenon)]**: 실생활 사례, 시범 실험, 영상, 또는 디지털 시뮬레이션을 통해 관찰 가능한 거시적 변화를 확인한다.
3. **[Step 3. 핵심 특징 주목 & 단순화된 과학 모형(Simplified Scientific Model)]**: 복잡한 현실에서 부수적 조건을 덜어내고 핵심 변인(입자, 힘의 화살표, 전하 흐름, 광선 등)만 남긴 **단순화된 모형·비유**로 원리를 시각화한다. *(※ 비유 사용 시 반드시 '대응하는 점'과 '실제 현상과 다른 한계/오개념 주의점'을 함께 명시)*
4. **[Step 4. 학생 사고·탐구·적용(Inquiry & Application)]**: 교과서 탐구/해보기 또는 단계별 발문을 통해 학생이 모형을 조작·적용하며 스스로 인과관계를 설명하게 한다.
5. **[Step 5. 현실 복귀 & 도입 질문 재방문(Return to Reality & Closure)]**: 단순화된 모형에서 얻은 법칙을 다시 복잡한 현실 현상과 도입 질문에 적용해 해결하고 마무리 학습지로 생각을 구조화한다.

### 2.2 인터랙티브 아웃라인 선택 메커니즘 (A/B/C 대안 + 레고 블록 조립형)
- AI가 단순히 획일적인 A/B/C 3개 안만 던지고 끝내는 것이 아니라, **실질적으로 다른 3가지 수업 경로(A/B/C 비교표)**와 함께 교사가 단계별로 골라 조립할 수 있는 **[구간별 선택 옵션(도입 1·2·3 / 모형화 1·2·3 / 탐구 1·2·3 / 마무리 1·2·3)]**을 제시합니다.
- 교사는 `"B안 기본에 도입만 A-1로 바꾸고, 모형화는 입자 충돌 시뮬레이션 중심으로 해줘"`처럼 대화형으로 즉시 아웃라인을 조립·수정한 뒤 **명시적 승인(`/시나리오-아웃라인-확정`)**을 거쳐 초안을 생성합니다.

### 2.3 마무리 학습지 구조 (시나리오·프리젠테이션 완전 연동)
- **파트 A [개념의 흐름과 빈칸 정리]**: `현실 현상 → 단순화된 모형 → 핵심 개념/법칙`으로 이어지는 쉬운 문단(5~8문장, 빈칸 ①~⑥) + **미니 모형 스케치/체크 칸**(예: 온도가 높을 때 입자 화살표 그리기).
- **파트 B [핵심 적용 문항]**: 교과서 성취기준 기반 객관식 2문항(현상 이해 1 + 모형·그래프 해석 1) + 짧은 서술형 1문항(핵심 원리 1~2문장 설명).
- **파트 C [과학적 생각의 변화 (개념 변화 성찰)]**: 도입 질문과 연결하여 `[수업 전 내 생각] → [관찰/모형에서 찾은 단서] → [수업 후 과학 용어로 바뀐 내 설명]`을 짧게 작성.
- **교사용 별첨 [정답·해설 및 AI 서술형 채점 연동 기준표]**: 정답, 허용 답안 범위, 대표 오개념 피드백, 그리고 Google Sheets 서술형 채점 도구에 바로 붙여넣을 수 있는 **채점 기준(Rubric) 요약** 포함.

## 3. 교사 성향·요구사항 누적 및 개선지침 생성 아키텍처

수업을 거듭할수록 교사의 피드백과 성향이 휘발되지 않고 정교해지도록 **3계층 누적 + 이중 반영(모듈형 스냅샷 & 버전업 전문)** 구조를 설계했습니다.

```
[수업 중 교사의 선택·수정·피드백]
       │
       ├──▶ ① [Tier 1: 이번 수업 한정 조건] ──▶ 현재 시나리오/슬라이드/학습지에만 즉시 반영 (영구 지침 미반영)
       │
       ├──▶ ② [Tier 2: 성향 관찰 & 피드백 장부 누적]
       │        ├─ 명시적 선언 ("앞으로도 항상 ~해줘", "내 기본 스타일로") ──▶ [장기반영 후보] 즉시 등록
       │        └─ 반복 선택·수정 패턴 ("매번 도입에 일상 비유 선택", "슬라이드 글자 축소 요청")
       │             ──▶ AI가 [관찰된 성향 후보]로 기록 후 산출물 확정 시 1줄 확인 질문
       │
       └──▶ ③ [Tier 3: 개선지침 생성 및 소스 동기화]
                ├─ 빠른 누적 (`/성향스냅샷`) ──▶ 지침 전체 교체 없이 [2-C. 교사 성향 프로필 패치 블록]만 출력 (Google Docs 지침에 붙여넣기 또는 노트로 소스화)
                └─ 정식 개정 (`/지침개선` → 승인 → `/지침개선-확정`) ──▶ 누적 피드백 분석표 + 계승 검증을 거친 차기 버전(v3.1, v3.2...) 최우선지침 전문 출력
```

### 왜 이 누적 구조가 효과적인가?
1. **일회성 선택의 성급한 일반화 방지**: 한 차시에서 시간 부족으로 실험을 뺐다고 해서 AI가 "이 교사는 실험을 싫어함"으로 지침을 왜곡하지 않도록, **선택한 결과보다 교사가 말한 '이유'와 '적용 범위(이번만 vs 앞으로도)'**를 분리 기록합니다.
2. **암묵적 성향의 자연스러운 발굴**: 교사가 일일이 "이걸 지침에 넣어줘"라고 말하지 않아도, 산출물을 수정하며 반복되는 요구(예: "수식보다 입자 그림을 먼저 보여줘", "서술형 문항에 조건 단어를 제시해줘")를 AI가 **성향 관찰 장부**에 모아두었다가 `/지침개선` 또는 `/성향스냅샷` 때 근거와 함께 제안합니다.
3. **Google Docs 연동 무중단 업데이트**: 최우선 지침 파일을 로컬 MD 파일 대신 **Google Docs 문서로 만들어 Gemini Notebook 소스에 연결**해 두면, `/성향스냅샷`이나 `/지침개선-확정` 결과를 Google Docs에 붙여넣고 노트북에서 **'소스 동기화(Sync)' 버튼 한 번**만 누르면 채팅 맞춤설정을 건드리지 않고도 영구 반영됩니다.
