# 프리젠테이션 제작 방식 비교 분석 및 Gemini Notebook × 외부 에이전트(Argon) 이원화 수업설계 아키텍처 (v3.2)

- **작성일**: 2026-11-08 (v3.2 개정)
- **적용 대상**: 중학교 과학(중1~중3) 및 전교과(국어·사회·수학·영어·예체능 등) 수업 설계
- **핵심 과제**:
  1. 교육 계정 Gemini 슬라이드(3.6 Flash 기반) 제작 방식과 강화된 **Gemini Notebook(구 NotebookLM) 스튜디오(Slide Deck)** 자체 제작 방식의 장단점을 다각도로 비교하여 최적의 하이브리드 워크플로우를 확정함.
  2. **Gemini Notebook**은 오직 **수업 산출물(인터랙티브 시나리오, 스튜디오 프리젠테이션, 3단 마무리 학습지) 고품질 생성**과 **개선용 기초 피드백 시그널 추출(`/피드백추출`)**에만 집중하고, **지침 개선 및 성향 누적은 외부 에이전트(Argon / 중앙 저장소)가 전담**하는 **v3.2 이원화 아키텍처**를 정립함.

## 1. 핵심 의사결정: 스튜디오(Slide Deck) vs Gemini 슬라이드(3.6 Flash)

### 1.1 두 방식의 기술적·교육적 특성 비교

수업 현장(과학의 입자·힘·회로 모형, 국어·사회의 구조도·타임라인, 수학의 도형-수식 매칭 등)의 관점에서 두 도구를 7가지 핵심 기준으로 비교 분석했습니다.

| 비교 항목 | **Gemini Notebook 스튜디오 (Slide Deck)** | **교육 계정 Gemini 슬라이드 (3.6 Flash)** | 수업 설계 관점 판정 |
| :--- | :--- | :--- | :--- |
| **① 전체 시각·이미지 품질** | **최상 (Nano Banana Pro 기반 렌더링)**<br>슬라이드 전체를 인포그래픽·다이어그램·비유 삽화가 조화된 고해상도 비주얼 레이아웃으로 생성 | **보통~낮음 (텍스트 박스 + 기본 도형 위주)**<br>개조식 텍스트 요약 위주이며 레이아웃이 단조롭고 개념 삽화 품질이 제한적 | **스튜디오 압승**<br>시각적 직관성이 중요한 수업에서 학생 몰입도 차이가 매우 큼 |
| **② 개념 구조도·모형 비교 표현력** | **우수**<br>거시적 현상과 미시적 모형(입자 충돌 화살표), 다관점 대조 레이아웃을 한 장에 직관적으로 시각화 가능 | **미흡**<br>교사가 별도로 시뮬레이션 캡처나 교과서 그림을 찾아 수동으로 붙여 넣어야 함 | **스튜디오 우위**<br>단, 스튜디오가 개념적 오류(화살표 방향 등)를 범하지 않도록 **사전 설계 프롬프트 통제** 필수 |
| **③ 완성 후 부분 편집성** | **제한적 (래스터/이미지 기반 한계)**<br>스튜디오 슬라이드는 이미지 렌더링 방식이라 `.pptx`로 내려받아도 글자 단위 직접 클릭 수정이 어렵고, 스튜디오 내 `Revise(수정)` 기능으로 슬라이드별 재생성을 해야 함 | **최상 (네이티브 Google Slides 개체)**<br>모든 텍스트 상자·도형·표를 마우스로 클릭해 1초 만에 수정·삭제·서식 변경 가능 | **Gemini 슬라이드(Flash) 우위**<br>학급별 실시간 빈칸 입력·오타 즉석 수정은 네이티브 슬라이드가 유리 |
| **④ 수정(`Revise`) 시 원본 소스 참조 여부** | **주의 필요 (2026 스튜디오 구조적 제약)**<br>최초 생성 시에는 소스를 읽지만, 생성 후 `Revise` 모드에서는 **원본 소스를 다시 읽지 않고** 수정 지시문만으로 새 덱을 재생성하며 쿼터를 소모함 | **프롬프트 재입력 또는 수동 편집**<br>교사가 직접 슬라이드에서 고치므로 AI 재생성 자체가 불필요 | **사전 아웃라인 확정으로 해결**<br>스튜디오 생성 전에 채팅에서 슬라이드 설계안을 먼저 확정해야 `Revise` 반복을 막을 수 있음 |
| **⑤ 한글 텍스트 렌더링 안정성** | **글자 수가 적을 때 우수 / 많을 때 깨짐 위험**<br>이미지 렌더링 특성상 한 슬라이드에 긴 문장이나 복잡한 표가 들어가면 한글 자소 깨짐·오탈자 발생 가능 | **완벽 (시스템 폰트 텍스트)**<br>긴 문장이나 복잡한 실험 결과표도 글자 깨짐이 전혀 없음 | **역할 분리로 해결**<br>스튜디오 슬라이드는 **핵심 키워드·발문(3줄 이내)**만 넣고 긴 설명·표는 시나리오·학습지로 분리 |
| **⑥ 교과서 근거 충실도 (할루시네이션 통제)** | **우수 (노트북 내 선택 소스 기반)**<br>선택된 소스(교과서·지도서·확정 시나리오 노트) 안에서만 내용을 추출 | **보통**<br>채팅에서 만든 긴 프롬프트를 옮기는 과정에서 일부 조건이 누락되거나 일반 지식이 섞일 수 있음 | **스튜디오 우위**<br>노트북 안에서 시나리오→프리젠테이션→학습지가 한 맥락으로 묶임 |
| **⑦ 교사 작업 동선 (Context Switching)** | **원스톱 (Gemini Notebook 내부 완결)**<br>채팅 설계 → 노트 소스 고정 → 스튜디오 생성까지 하나의 노트북 안에서 진행 | **이원화**<br>노트북 채팅에서 프롬프트 생성 → 복사 → Gemini/Google Slides 이동 → 생성 후 수동 편집 | **스튜디오 우위**<br>단원별 노트북 하나에 모든 수업 자산이 축적됨 |

### 1.2 최종 채택 전략: **"스튜디오 중심(Primary 85%) + 부분 편집 보완(Hybrid 15%) 파이프라인"**

> **결론**: 전체적인 프리젠테이션의 시각적 완성도와 **'현상-모형·구조도 시각화 품질'**을 극대화하기 위해 **Gemini Notebook 스튜디오(Slide Deck) 자체 제작 방식을 주력(Primary) 프로세스로 채택**합니다. 동시에 스튜디오의 유일한 약점인 **'부분 편집의 불편함'과 '교사 시나리오 의도 반영 문제'를 4단계 브릿지 기술로 완벽히 보완**합니다.

#### 스튜디오의 약점을 해결하는 4대 핵심 엔지니어링 기법

1. **[기법 1] '확정 설계안의 소스화 (Note-to-Source Pinning)'로 교사 의도 100% 강제**
   - 스튜디오에서 바로 교과서 PDF만 선택해 슬라이드를 만들면 AI가 임의로 교과서를 요약해 버립니다.
   - 대신 **① 채팅에서 인터랙티브 아웃라인으로 시나리오 확정 → ② 채팅에서 스튜디오용 슬라이드 설계안(장별 제목·표시 문구·시각 모형 지시) 확정 → ③ 이 확정 설계안을 노트북의 `[메모(Note)로 저장]` 후 `[소스로 변환(Convert to source)]` → ④ 스튜디오 Slide Deck 생성 시 이 '확정 설계안 소스'를 핵심 소스로 선택(운영지침 소스는 체크 해제)**하여 생성합니다.

2. **[기법 2] '1슬라이드 1메시지 · Text-Light, Visual-Rich' 한글 깨짐 원천 차단 규칙**
   - 스튜디오 렌더링 후 글자를 일일이 고칠 필요가 없도록, 애초에 슬라이드 화면에 들어갈 텍스트를 **제목 1줄(15자 이내) + 핵심 문구/발문 2~3줄(줄당 20~25자 이내, 개조식)**로 제한합니다.
   - 교사의 상세한 설명 대사, 예상 학생 반응, 실험 유의사항은 슬라이드에 적지 않고 **확정 시나리오(교사용 대본)**에 두며, 학생이 읽고 써야 할 긴 문장과 표는 **3단 마무리 학습지**에 배치합니다.

3. **[기법 3] 생성 후 '자가 완결형 Revise 지시문' (`/프리젠테이션-부분수정`)**
   - 스튜디오 `Revise` 모드는 원본 소스를 다시 읽지 않으므로, 노트북 채팅에서 `/프리젠테이션-부분수정` 명령을 통해 **정확한 용어·수치·수정 문구가 모두 포함된 '자가 완결형 슬라이드별 Revise 지시문'**을 뽑아 `Pending Changes`에 한 번에 입력합니다.

4. **[기법 4] 실시간 판서·빈칸 입력용 슬라이드만 'Gemini 3.6 Flash 부분 패치' (`/슬라이드-플래시패치`)**
   - 수업 중 교사가 전자칠판이나 슬라이드에서 학급별 측정값이나 발표 의견을 실시간으로 타이핑해야 하는 1~2장의 슬라이드는 `/슬라이드-플래시패치 [슬라이드 번호]`를 요청해 **교육 계정 Gemini(3.6 Flash)로 즉시 편집 가능한 Google Slides로 생성**하여 끼워 넣습니다.

## 2. 인터랙티브 수업설계 3대 산출물 구조

### 2.1 5단계 핵심 인지 흐름 (Cognitive Flow)
1. **[Step 1. 전수업 연결 & 배움의 필요성(Need-to-Know)]**: 법칙·용어를 바로 정의하지 않고, 기존 상식으로 설명되지 않는 현상이나 질문을 던져 학생 머릿속에 **'왜 이 개념이 필요한지' 받아들일 자리**를 먼저 만든다.
2. **[Step 2. 구체적 현상·맥락·원자료 관찰(Concrete Context)]**: 실생활 사례, 시범 실험, 본문 지문, 사료 등을 통해 구체적 특징을 확인한다.
3. **[Step 3. 핵심 특징 주목 & 단순화된 모형·구조도(Simplified Model / Diagram)]**: 복잡한 현상·자료에서 부수적 조건을 덜어내고 핵심 변인·구조만 남긴 **단순화된 과학 모형·구조도**로 원리를 시각화한다. *(※ 비유 사용 시 반드시 '대응하는 점'과 '한계/오개념 주의점'을 병기)*
4. **[Step 4. 학생 사고·탐구·적용(Inquiry & Application)]**: 교과서 탐구/활동 또는 단계별 발문을 통해 학생이 모형·구조를 적용하며 스스로 인과관계를 설명하게 한다.
5. **[Step 5. 현실·맥락 복귀 & 도입 질문 재방문(Return & Closure)]**: 배운 원리를 다시 처음의 도입 질문과 실제 맥락에 적용해 해결하고 3단 마무리 학습지로 생각을 구조화한다.

### 2.2 3단 마무리 학습지 구조 (시나리오·프리젠테이션 완전 연동)
- **파트 A [핵심 흐름 요약 빈칸 & 미니 모형/구조 체크]**: 쉬운 문단(5~8문장, 빈칸 ①~⑥) + **미니 모형/구조도 직접 표시 칸 1개**.
- **파트 B [핵심 적용 문항]**: 객관식 2문항(개념 이해 1 + 모형·자료 해석 1) + 조건 제시형 짧은 서술형 1문항.
- **파트 C [생각의 변화 (메타인지 성찰)]**: `[① 수업 전 내 생각] → [② 생각을 바꾼 결정적 단서] → [③ 수업 후 배운 개념으로 바뀐 내 설명]`.
- **교사용 별첨 [정답·해설 및 AI 서술형 채점 연동 기준표]**: 정답, 학생 일상어 허용 범위, 대표 오개념 피드백, Google Sheets AI 채점 연동 루브릭 표.

## 3. v3.2 핵심 아키텍처: Gemini Notebook(산출물 집중) ↔ 외부 에이전트 Argon(지침 개선 전담) 이원화 구조

노트북 채팅 안에서 400줄짜리 지침 전문을 직접 수정·출력하게 하면 토큰 소모가 크고 산출물 품질이 분산됩니다. **v3.2 아키텍처는 두 시스템의 역할을 명확히 분리**했습니다.

```
┌────────────────────────────────────────────────────────────────────────────┐
│ [Gemini Notebook] — 수업 산출물 3종 생성 & 피드백 시그널 추출 전담         │
├────────────────────────────────────────────────────────────────────────────┤
│  1. 산출물 제작 집중:                                                      │
│     • `/시나리오` (A/B/C 비교표 + 블록 조립 → 분 단위 대본)                │
│     • `/프리젠테이션` (스튜디오 3종 패키지 + 자가 완결형 Revise / 패치)    │
│     • `/학습지` (3단 마무리 학습지 + 교사용 AI 서술형 채점 루브릭)         │
│  2. 동일 차시 전방 전파 (Forward-Propagation):                             │
│     • 시나리오 수정 시 파악된 교사 선호를 같은 수업 슬라이드·학습지에      │
│       자동으로 즉시 상속 반영                                              │
│  3. 외부 전달용 시그널 추출 (`/학습지-확정` 자동 또는 `/피드백추출` 명령): │
│     • 4대 접점(초기 조건, 블록 선택, 수정 Before→After 델타, 확정)에서     │
│       교사 성향(`D1~D6`)과 신뢰도(`L1/L2`, 일회성 `L0` 분리)를 분석하여    │
│       단원 소재를 보편 규칙으로 추상화한 **[Markdown 요약표 + JSON 패키지]** 출력 │
└─────────────────────────────────────┬──────────────────────────────────────┘
                                      │ (교사가 JSON/Markdown 패키지 복사 전달)
                                      ▼
┌────────────────────────────────────────────────────────────────────────────┐
│ [외부 에이전트 (Argon / 중앙 Git 저장소)] — 성향 누적 & 지침 버전업 전담   │
├────────────────────────────────────────────────────────────────────────────┤
│  1. 전달받은 JSON/Markdown 피드백 리포트를 파싱하여 `2-C(D1~D6)` 프로필과  │
│     지침 본문 조항을 중복 없이 정밀 병합·개정                              │
│  2. 중앙 Git 저장소(`education/수업설계`) 버전업 커밋·푸시 및              │
```
